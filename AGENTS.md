# Instructions for coding assistants

Jolt is a beginner-friendly JavaScript learning platform: **PLAY. GET BETTER.**
This file only points to the documents that own the rules, so nothing here can
drift from them.

## Before any substantial task, read

1. `docs/JOLT_VISION.md`: the product blueprint (identity, the places, the
   decision criteria every change is judged against).
2. `docs/DEVELOPMENT_WORKFLOW.md`: the canonical workflow (inspect → diagnose
   → propose → approve → implement → verify → review → handoff), the commands,
   database safety, browser QA, the definition of done and the release
   checklist.
3. `docs/ROADMAP.md`: what is done, what is next, release blockers and open
   decisions.
4. `docs/KNOWN_LIMITATIONS.md`: what is already known not to work.

## Then, as the task requires

- `docs/LEARNING_LOOP.md`: how Jolt teaches; evidence and demonstration.
- `docs/CURRICULUM_ARCHITECTURE.md` and `docs/CONCEPT_CONTRACT_assignment.md`:
  the curriculum model.
- `docs/GAMEPLAY_SPEC.md` and `docs/GAME_DESIGN.md`: what each game is for, and
  the bar it must meet.
- `README.md`: setup, running and tests.

Where these documents disagree, `docs/DEVELOPMENT_WORKFLOW.md` governs process
and `docs/JOLT_VISION.md` governs product direction. Say so when you find a
conflict instead of picking one silently.
